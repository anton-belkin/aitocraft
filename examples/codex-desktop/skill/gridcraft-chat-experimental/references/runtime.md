# Локальный runtime

Skill установлен глобально, но использует уже собранный экспериментальный runtime на этом Mac. Его расположение задаёт `../runtime.json`; это данные установки, а не настройка конкретного проекта.

`scripts/gridcraft_chat.py status` проверяет общий сервер и текущий ID чата. Если Desktop открыт обычным способом, его внутренний stdio App Server недоступен внешнему обработчику. Закрой Desktop самостоятельно через Cmd+Q и запусти `Start Codex Desktop.command` из `stateDir`, записанного в runtime.json. Launcher откроет исходный чат; для другого чата используй `shared_codex_desktop.py --launch --thread <точный UUID>` в Terminal. Не останавливай текущий Desktop и не редактируй его глобальную конфигурацию автоматически.

Если сервер работает, но нужный чат не загружен, открой этот чат в Desktop и повтори status. При недоступном выбранном чате первый вопрос может создать новый настоящий Desktop-чат; панель Agent должна показать «Другой чат». Исходная метка книги при этом остаётся неизменной.

Если порт 45124 после перезапуска Mac не отвечает, повторный `issue` запускает локальный HTTP-сервис. Запуск `Start GridCraft.command` поднимает сервис ссылок; для отдельного восстановления можно запустить `gridcraft_links.py serve` рядом с helper из runtime.json (с правильным GRIDCRAFT_CODEX_STATE_DIR). Само открытие ссылки не запускает модель, не отправляет вопросов и не принимает предложений.

Не выдавай localhost-ссылку как переносимую веб-публикацию: другой компьютер не имеет этих tickets или локальных файлов. Формат `.xlsx` и существующий файл сохраняются; генерация ссылки не добавляет происхождение чужому файлу.

Наличие общего App Server и AItoCraft не гарантирует доступность браузера/Computer Use в том же запуске. Если UI-инструменты сообщают `native pipe closed before response`, не выдавай вызовы API за реальные клики. В явном синтетическом QA можно проверять штатные команды приложения по запросу пользователя и указывать этот предел проверки; обычные предложения по файлам остаются на принятие человеком.
